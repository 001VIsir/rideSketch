```java
// 向量相似度计算
public float cosineSimilarity(float[] vec1, float[] vec2) {
    float dotProduct = 0, norm1 = 0, norm2 = 0;
    for (int i = 0; i < vec1.length; i++) {
        dotProduct += vec1[i] * vec2[i];
        norm1 += vec1[i] * vec1[i];
        norm2 += vec2[i] * vec2[i];
    }
    return dotProduct / (float)(Math.sqrt(norm1) * Math.sqrt(norm2));
}
```

### 第一部分：基础概念（必考）

#### Q1: 什么是 AI Agent？它与普通的 LLM 聊天机器人有什么本质区别？

**核心区别**：

| 维度 | 普通LLM聊天 | AI Agent |
|------|------------|----------|
| 交互模式 | 单轮、无状态 | 多轮、有状态 |
| 主动性 | 被动响应 | 主动决策和执行 |
| 能力边界 | 仅文本生成 | 可调用工具、访问外部系统 |
| 记忆 | 无持久记忆 | 短期+长期记忆系统 |

**本质公式**：
```
Agent = LLM + Planning + Memory + Tools
```

**结合本项目**：
> 在 rideSketch 项目中，我们的 AI 路线规划模块就是一个典型的 Agent 应用。用户输入"我想从北邮骑行到天安门，沿途风景要好"，系统会：
> 1. LLM理解意图 → 提取起点、终点、偏好
> 2. 调用高德地图API → 获取路线数据
> 3. 根据偏好筛选 → 推荐最优路线
> 4. 返回结构化结果 → 前端渲染

---

#### Q2: 请解释 ReAct (Reasoning + Acting) 模式的核心思想

**核心思想**：让 Agent 在执行动作之前先进行显式推理，形成 "思考-行动-观察" 的循环。

**执行流程**：
```
Thought (思考) → Action (行动) → Observation (观察) → Thought → ...
```

**具体示例**（本项目的AI路线规划）：
```
用户问：我想规划一条30公里的北京骑行路线，风景要好

Agent执行过程：
┌─────────────────────────────────────────┐
│ Thought 1: 用户想规划30km骑行路线，      │
│           需要确定起点和途经点            │
├─────────────────────────────────────────┤
│ Action 1: 调用高德地图搜索API            │
│          获取北京热门骑行景点             │
├─────────────────────────────────────────┤
│ Observation 1: 颐和园、圆明园、香山...   │
├─────────────────────────────────────────┤
│ Thought 2: 根据距离计算最佳组合          │
├─────────────────────────────────────────┤
│ Action 2: 调用路线规划API验证距离        │
├─────────────────────────────────────────┤
│ Final Answer: 推荐北邮→颐和园→圆明园     │
│              路线，约28公里               │
└─────────────────────────────────────────┘
```

**为什么能减少幻觉？**
1. 推理过程外显化，可追溯
2. 每步都有实际观察作为验证
3. 避免模型凭空编造信息

#### Q4: ReAct 与 Planning & Extractor 两种范式有什么区别？

**对比分析**：

| 维度 | ReAct | Planning & Extractor |
|------|-------|---------------------|
| **工作流程** | 推理-行动循环，动态迭代 | 规划→执行→提取，线性阶段 |
| **决策灵活性** | 高，可根据中间结果调整 | 低，计划一旦制定相对固定 |
| **工具调用** | 不确定，由模型动态决定 | 确定，由计划步骤决定 |
| **实现复杂度** | 需设计循环机制和停止条件 | 相对简单，各阶段可独立优化 |

**适用场景**：
- **ReAct 适合**：开放式探索任务、需要多步推理（如本项目的AI路线规划）
- **Planning & Extractor 适合**：流程清晰、输出格式要求严格（如报表生成）

**本项目 RAG 实现**（`RagServiceImpl.java`）：

```java
// 1. 查询向量化
float[] queryEmbedding = embeddingService.embed(query);

// 2. 向量检索 - 余弦相似度计算
List<KnowledgeEntry> results = knowledgeBase.entrySet().stream()
    .map(entry -> new SearchResult(
        entry.getKey(),
        entry.getValue(),
        cosineSimilarity(queryEmbedding, entry.getValue().getEmbedding())
    ))
    .sorted((a, b) -> Double.compare(b.getScore(), a.getScore()))
    .limit(topK)
    .collect(Collectors.toList());

// 3. 构建增强上下文
String context = results.stream()
    .map(r -> r.getEntry().getContent())
    .collect(Collectors.joining("\n\n"));

// 4. LLM生成答案
String systemPrompt = SYSTEM_PROMPT.replace("{context}", context);
return chatClient.prompt().system(systemPrompt).user(query).call().content();
```

**关键优化点**：
1. **混合检索**：向量检索 + 关键词检索
2. **重排序**：使用 Cross-Encoder 精排
3. **引用溯源**：每个回答标注来源，避免"胡编"

**避免幻觉积累的策略**：
1. **记忆隔离**：不同任务/会话的记忆分开存储
2. **置信度校验**：对检索到的记忆进行可信度评估
3. **定期清理**：清除过时或冲突的记忆
4. **来源追踪**：每条记忆记录来源和时间戳

**核心优势**：

| 维度 | 单Agent | Multi-Agent |

| **专业能力** | 通才，样样通样样松 | 专才，各司其职 |

```
   A ←──→ B
```

### 第五部分：生产部署与工程化（加分项）

#### Q8: Agent 在生产环境中面临哪些挑战？如何优化成本和延迟？

**主要挑战**：

| 挑战 | 具体问题 | 解决方案 |
|------|----------|----------|
| **成本** | Token消耗巨大 | 模型路由、缓存、小模型分流 |
| **延迟** | 多步推理慢 | 流式输出、并行工具调用 |
| **可靠性** | 幻觉、死循环 | 超时控制、人工兜底 |
| **安全** | Prompt注入 | 输入过滤、权限控制 |

**成本优化策略**：

```python
# 模型路由策略
def route_query(query):
    complexity = analyze_complexity(query)

    if complexity == "simple":
        return "gpt-4o-mini"  # 便宜、快速
    elif complexity == "medium":
        return "gpt-4o"       # 平衡
    else:
        return "gpt-4"        # 复杂任务用大模型
```

**本项目优化实践**：
- 使用本地 Ollama (qwen3:8b) 替代云服务，节省 API 费用
- Redis 缓存热门路线查询结果
- 前端地图搜索直接调用高德JS API，减少后端压力

#### Q10: 请结合你的项目，讲解 RAG 是如何实现的？

**回答模板**：

> 在 rideSketch 项目中，我实现了一个骑行知识问答系统，使用 RAG 技术让用户可以询问骑行相关问题。
>
> **技术选型**：
> - Embedding 模型：Ollama 的 nomic-embed-text（768维向量）
> - 向量存储：Redis（生产可用 Milvus/ChromaDB）
> - LLM：Ollama qwen3:8b
>
> **实现步骤**：
>
> 1. **知识库构建**：整理97条骑行知识，分为9个类别
>
> 2. **向量化存储**：
> ```java
> public void loadKnowledgeBase() {
>     for (KnowledgeEntry entry : knowledgeList) {
>         float[] embedding = embeddingService.embed(entry.getContent());
>         entry.setEmbedding(embedding);
>         vectorStore.put(entry.getId(), entry);
>     }
> }
> ```
>
> 3. **语义检索**：
> ```java
> public List<KnowledgeEntry> search(String query, int topK) {
>     float[] queryEmbedding = embeddingService.embed(query);
>     return vectorStore.values().stream()
>         .sorted((a, b) -> Double.compare(
>             cosineSimilarity(queryEmbedding, b.getEmbedding()),
>             cosineSimilarity(queryEmbedding, a.getEmbedding())))
>         .limit(topK)
>         .collect(Collectors.toList());
> }
> ```
>
> 4. **增强生成**：
> ```java
> String context = searchResults.stream()
>     .map(KnowledgeEntry::getContent)
>     .collect(Collectors.joining("\n\n"));
>
> String prompt = SYSTEM_PROMPT.replace("{context}", context);
> return chatClient.prompt().system(prompt).user(query).call().content();
> ```
>
> **遇到的挑战**：
> - Spring AI embedding API兼容问题 → 直接调用 Ollama 原生 API
> - 向量维度对齐 → 使用同一 embedding 模型

**回答模板**：

> 在项目中，我从多个层面处理 AI 调用的异常：
>
> **1. 服务层异常处理**：
> ```java
> @Service
> public class AIRouteServiceImpl implements AIRouteService {
>
>     public AIRoutePlanningResult planRoute(String description, String city) {
>         try {
>             // 调用 Ollama
>             String response = chatClient.prompt()
>                 .system(SYSTEM_PROMPT)
>                 .user(buildUserPrompt(description, city))
>                 .call()
>                 .content();
>
>             return parseResponse(response);
>         } catch (Exception e) {
>             log.error("AI route planning failed", e);
>             // 返回降级结果
>             return AIRoutePlanningResult.fallback("AI服务暂时不可用，请稍后重试");
>         }
>     }
> }
> ```
>

> ```properties
> spring.ai.ollama.chat.options.temperature=0.7

> ```
>
> **3. 重试机制**：
> ```java
> @Retryable(value = {IOException.class}, maxAttempts = 3, backoff = @Backoff(delay = 1000))
> public String callOllama(String prompt) {
>     // 调用逻辑
> }
> ```
>
> **4. 用户友好提示**：
> - AI 不可用时，引导用户使用手动路线规划
